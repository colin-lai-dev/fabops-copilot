# ADR-0004: 合成文件的產生方式

- 日期：2026-11-08
- 狀態：已採用

## 背景

SOP 與異常報告必須夠擬真，檢索分數才不會偏高；同時事實要受控，eval 的標準答案才可靠。

## 選項

| 選項 | 優點 | 缺點 |
| --- | --- | --- |
| A. 純規則與模板 | 可重現、免費 | 文字生硬，檢索分數偏高 |
| B. 規則產生骨架，地端 LLM 潤飾文字 | 事實受控、文字擬真 | 要多寫一個事實檢查 |
| C. 全部由 LLM 生成 | 最擬真 | 事實不受控，標準答案不可靠 |

## 決定

選擇 B。

## 理由

事實與標準答案來自規則，文字擬真度來自 LLM，兩個需求都能滿足；用地端模型不花 API 費用。

## 後果

- 流程：`skeleton`（結構化事實、metadata、標準答案，JSON）→ `render`（模板）→
  `polish`（Ollama 改寫）→ `verify`（檢查關鍵事實仍在）→ 提交進 repo。
- 骨架以固定 random seed 產生；潤飾結果提交進 repo，之後重跑 seed 不需要 LLM。
- `verify` 未通過的文件改用模板版本，並記錄比例到 experiments.md。
- 髒資料（新舊版、表格、縮寫、錯字與口語）在骨架或 render 階段以規則注入，
  不依賴 LLM，確保可控、可統計。
- 潤飾用的 prompt 與模型版本記錄在 experiments.md。
