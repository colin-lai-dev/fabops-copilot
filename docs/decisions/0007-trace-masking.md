# ADR-0007: Trace 遮罩規則

- 日期：2026-11-08
- 狀態：已採用

## 背景

Trace 是一個資料出口：記錄檢索結果與工具輸出時，可能把機密內文送到 Langfuse 雲端，
讓沒有權限的人（包含開發者本身）看到。

## 選項

| 選項 | 優點 | 缺點 |
| --- | --- | --- |
| A. 嚴格遮罩 + 本機除錯模式 | 規則單純、容易證明不洩漏 | 雲端 trace 不能直接看內文 |
| B. 依等級遮罩 | 除錯方便 | 規則複雜，較難證明 |
| C. 不遮罩，靠 Langfuse 存取控管 | 最省事 | 違反出口檢查原則 |

## 決定

選擇 A。

## 理由

「送出的 trace 不含任何內文」是一條容易用測試驗證的規則，
也和「權限檢查做在每個資料出口」的原則一致。

## 後果

- 送到 Langfuse 的欄位：文件 ID、機密等級、內容雜湊、長度、工具名稱、步驟順序、
  token、延遲、成本。使用者問題與最終回答也不送出內文，只送雜湊與長度。
- 本機除錯模式（`FABOPS_DEBUG_TRACE=1`）：完整內容只寫入本機 `.cache/debug-traces/`
  （已 gitignore），永不送出。
- 洩漏測試集的日誌路徑：檢查送出的 trace payload 中不含任何受限文件內文。
