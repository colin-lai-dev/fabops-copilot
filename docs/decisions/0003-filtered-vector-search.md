# ADR-0003: 權限過濾與向量檢索的搭配

- 日期：2026-11-08
- 狀態：已採用

## 背景

ANN 索引（例如 HNSW）加上 WHERE 篩選時，可能先取出 top-k 再被權限條件濾掉大半，
導致低權限使用者找回的結果太少，檢索品質隨權限而下降。

本專案約 190 份文件，切塊後預估數千筆。

## 選項

| 選項 | 優點 | 缺點 |
| --- | --- | --- |
| A. 精確搜尋，不建 ANN 索引 | 篩選結果完全正確，無召回損失；設定最少 | 規模很大時速度不夠 |
| B. HNSW + pgvector iterative scan | 可擴展到大規模 | 要調參數，並另外驗證篩選後的召回率 |
| C. 依廠區或等級分割索引 | 大規模、條件固定時效果好 | 本規模不需要，維護較麻煩 |

## 決定

選擇 A：先以權限條件篩選，再對符合的 chunk 做精確向量相似度計算。
BM25 側同樣先套用權限條件，再排序。

## 理由

在數千筆的規模下，精確搜尋只需毫秒級，又能保證篩選結果正確，
讓權限與檢索品質的實驗不被 ANN 的近似誤差干擾。

## 後果

- 在 experiments.md 記錄實際 chunk 數與檢索延遲。
- 換成 B 或 C 的條件：chunk 數到數十萬筆以上，或 p95 檢索延遲超過可接受範圍。
  屆時需補做「篩選後召回率」的驗證。
