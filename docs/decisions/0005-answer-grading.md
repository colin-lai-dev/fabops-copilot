# ADR-0005: 答案的評分方式

- 日期：2026-11-08
- 狀態：已採用

## 背景

面試官第一個追問會是「怎麼判對錯」。評分要可信、可重現，又要控制成本。
由於合成資料有結構化骨架（ADR-0004），多數題目都有明確的標準事實。

## 選項

| 選項 | 優點 | 缺點 |
| --- | --- | --- |
| A. 事實題用程式比對，開放題用 LLM judge | 多數題免費且穩定；judge 只用在必要處 | 需要為題目標註題型與關鍵事實 |
| B. 全部用雲端 LLM judge | 做法統一 | 成本高、較不穩定 |
| C. 全部用地端 judge | 免費 | 一致率可能不足，說服力弱 |

## 決定

選擇 A。

## 理由

標準事實來自骨架，程式比對既便宜又可重現；LLM judge 只留給無法用規則判斷的開放題。

## 後果

- 每題標註：題型、關鍵事實清單、應引用的文件 ID、是否應拒答。
- 事實題：檢查回答是否包含所有關鍵事實（容許同義詞與縮寫對照表）。
- 拒答題：檢查是否拒答，且未洩漏任何受限文件內容。
- 開放題：LLM judge 依評分準則給分。test 用雲端中階模型，dev 用地端模型；
  兩者都以 Colin 標註的 50 題報告與人工的一致率。
- 引用正確率：比對回答引用的文件 ID 與標準答案。
- 題目 dev/test 比例 40/60，依題型分層切分；test 目標 100 題以上。
- 評分邏輯由 Colin 親手撰寫（`evals/score.py`）。

## 修訂（2026-11-08）：評分細節的預設規則

由規劃者依 Colin「非重要決策代為決定」的偏好先定預設值；Colin 撰寫 `evals/score.py` 時可推翻，
推翻時更新本段並在 `tests/test_score.py` 補上對應案例。

1. **Recall@5**：命中比例（應引用文件中有幾份出現在前 5 名 ÷ 應引用文件數）。另外報告 Hit@5（至少命中一份）。
2. **數字比對**：數字前後不得緊鄰其他數字或小數點，「145 mTorr」不算包含「45 mTorr」。
3. **正規化**：比對前做 NFKC（全形轉半形）、去除空白、單位不分大小寫，同義詞與縮寫依 `evals/synonyms.py`。
4. **拒答判定**：以系統輸出的 `refused` 旗標為準；旗標與回答文字不一致（例如旗標為否但文字表示無法回答）時，
   另計 `refusal_mismatch` 指標，不改變該題判定。
5. **引用正確**：必須引用全部應引用文件，且不得引用已被取代的舊版 SOP（`old_version` 題的重點）。
   另外報告引用精確率（引用中屬於應引用文件的比例），不納入對錯判定。

## 修訂（2026-11-09）：人工標註的「部分」

由規劃者依 Colin 偏好代決（交接指示 003）。

6. **人工標註「部分」**：主要指標以嚴格標準計算，「部分」算**不通過**；另外報告寬鬆比例（「部分」也算通過），
   兩個數字並列並各自標 n。judge 一致率以嚴格標準為主。實作：`JudgeLabel.partial`、`evals/label_sheet.py` 的 `pass_rates`。
